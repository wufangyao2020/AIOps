## 最小策略

保留旧 `fingerprint` 为审计标识。独立模块 `global_signal_alert_policy.py` 比较语义快照；不把股票Top10作为去重键，以免遗漏同股票、同最高等级下的新事件。

| 类型 | 行为 |
| --- | --- |
| 首次P1/P2触发 | 发布 |
| 已恢复至非活跃，再次触发 | 发布，episode随下一次快照保留，失败可重试 |
| P2→P1、新指标阈值命中/升级 | 发布 |
| 新P1/P2正式事件、同文件实质内容修订 | 发布，显示新增事件标题与来源 |
| 活跃信号方向改变 | 发布 |
| 数值变化 | 相对上次成功发布基线累计达到5%发布；较小变化仅记录 |
| 稳定信号、纯日期推进、重复抓取时间变化 | 不发布，跨日规则相同 |
| 数据源失败/恢复 | 独立进入Actions warning和step summary；不混入产业Issue |
| WASDE固定模板的整页哈希P2 | 保留历史和原始分级，单列待核实warning及summary；不独立发布产业Issue |
| WASDE真实P1，或已标记confirmed_material的P2 | 不适用页面哈希例外，照常判断发布 |

5%是最小实现的通用默认值，不是经金融回测得出的最佳阈值。等级升级、方向变化、新阈值、新事件无需等待5%。后续可按单位、波动率和研究反馈设置逐信号参数。

事件签名使用 event_key、标题、摘要、方向、等级、来源，不使用 fetched_at 或重复维护的日期。事件列表不再截断前20条，避免第21条新P1无法比较。已通知事件签名在发布回执中保留，避免窗口收缩造成遗忘。

## 发布可靠性

`publish_global_signal_alert.cjs` 使用Issues列表API、所有状态、创建时间倒序并翻页，避开搜索索引延迟。只接受 github-actions[bot] 的 v1 发布回执，忽略PR和人工正文。已关闭Issue仍参与去重。

回执包含在创建成功的Issue正文中。生成数据时的git提交不是“已经通知”的凭证。API发布失败，下次仍与上次成功回执比较；API返回超时但实际创建成功时，下次列表读取能发现回执。无法读取回执或版本不支持则报错，不静默抑制新风险。

上次运行的快照持久化在 latest_alert.json，负责健康变化和触发episode延续；通知增量以成功回执为准。失败源保留既有信号状态，不把数据缺失当作恢复。取消 `cancel-in-progress: true`，减少在数据提交与Issue发布之间被后续运行取消的窗口。

旧Issue没有语义快照，无法安全推断完整已通知信息；上线后第一次有效P1/P2将发布一次建立v1基线，之后生效。没有修改/关闭#106、#107，也没有回填伪造回执。
